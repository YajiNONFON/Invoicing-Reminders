# Design decisions

The choices that shaped this project, why they were made, and what they cost.

| Decision                                                                                                        | Why                                                                                                                                                  | Trade-off                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Money is stored as integer cents** (`totalCents`, `unitPriceCents`)                                           | Decimal arithmetic is approximate (`0.1 + 0.2` is `0.30000000000000004`). Integers add up exactly. Decimals only appear when an amount is displayed. | Clients must send cents, and amounts are capped by a 32-bit integer (about 21 million dollars).                                                                    |
| **The server computes every total**                                                                             | A total sent by a client could disagree with its lines. Any `totalCents` in the request body is ignored.                                             | None worth noting.                                                                                                                                                 |
| **Dates are calendar days** (`YYYY-MM-DD`, `@db.Date` columns)                                                  | An invoice due on the 20th is due on the 20th in every timezone. A timestamp would shift by an hour or a day.                                        | "Today" needs a timezone, so it is explicit (`APP_TIMEZONE`, default `Africa/Porto-Novo`).                                                                         |
| **Overdue means `dueDate < today`**                                                                             | An invoice due today is not late yet.                                                                                                                | Reminders start the day after the due date.                                                                                                                        |
| **Invoice numbers come from a counter table** (`FAC-0001`) updated in a transaction, plus a `unique` constraint | `count() + 1` produces duplicates when two requests arrive together.                                                                                 | One extra table and a short row lock when creating an invoice.                                                                                                     |
| **A reminder is unique per invoice and day**, enforced by the database (`@@unique([invoiceId, day])`)           | The rule holds even if the job runs twice or two runs overlap, which an application-level check cannot promise.                                      | Reminders are inserted with "skip duplicates" and the number actually created is counted.                                                                          |
| **Status changes are one guarded SQL update** (`UPDATE … WHERE status IN (allowed)`)                            | Two simultaneous requests cannot both move an invoice, and a payment is only recorded when the status really changed.                                | Rejected moves are detected after the fact and answered with `409`.                                                                                                |
| **Allowed transitions are a table**: draft→sent, sent→paid, sent→overdue, overdue→paid                          | One place to read the rules, and one test for each of the 16 pairs.                                                                                  | Cancelling or re-opening an invoice is not possible.                                                                                                               |
| **A daily `node-cron` job runs inside the API process** (`OVERDUE_CRON`)                                        | One thing to deploy, easy to demo.                                                                                                                   | Not suitable for several API instances: each one would run the job. The unique constraint keeps this harmless, but a real deployment would use a single scheduler. |
| **A `today` override on the job endpoint, outside production only**                                             | Lets a demo or a test simulate another day.                                                                                                          | Ignored when `NODE_ENV=production`, so nobody can force reminders there.                                                                                           |
| **Modular monolith, layered by module** (routes → controller → service → repository)                            | Small enough to read in an evening. Services hold business rules only, repositories hold every Prisma query, controllers handle HTTP only.           | More files than a flat layout.                                                                                                                                     |
| **Validation with zod, one error shape** (`{ "message": "..." }`)                                               | Inputs are checked at the edge and the front end handles a single error format.                                                                      | None worth noting.                                                                                                                                                 |
| **Swagger is written next to the routes** (`@openapi` comments in `*.routes.ts`)                                | The documentation changes in the same commit as the route.                                                                                           | Comments in code files can be verbose.                                                                                                                             |
| **Tests**: the HTTP layer mocks repositories, a few tests run against a real PostgreSQL in CI                   | Fast feedback locally, and real proof for the rules that depend on the database (unique reminder, concurrent numbering).                             | Database tests only run when `RUN_DB_TESTS=true`.                                                                                                                  |
| **Pinned versions**: Prisma 7, TypeScript 6                                                                     | The newest majors changed APIs or broke the linter at the time of writing.                                                                           | Upgrade deliberately, later.                                                                                                                                       |
| **Backend only in this repository**                                                                             | The project is about the automation. The demo front end stays out of it.                                                                             | The API contract (`docs/API.md`) is the only link between the two.                                                                                                 |
| **Docker Compose for PostgreSQL, GitHub Actions for CI**                                                        | A clone starts in a few commands, and every pull request runs lint, build and tests.                                                                 | Requires Docker locally.                                                                                                                                           |

## What this project deliberately does not do

- **Send emails.** A reminder is recorded (who, which invoice, when, with which subject). Sending it through an email provider is the natural next step.
- Multi-currency, VAT, or user accounts.
- Edit or cancel an invoice after it is created.
